# Проект 4.

API для создания онлайн-школы, реализованный на Django REST Framework с использованием 
PostgreSQL, Redis и Celery для асинхронных задач.

## **Установка:**

Версия python для данного проекта `^3.13`
Версия Django для данного проекта `^5.2`
Установленный Docker и Docker Compose (версия 3.9 или выше)

1. Установите Poetry:
```
https://install.python-poetry.org | python -
```
2. Клонируйте репозиторий:
```
git clone https://github.com/KolDaria/drf_project
```
3. Установите зависимости:
```
poetry add requests
```

## **Использование:**

1. Создайте файл `.env`:
Скопируйте содержимое файла `.env.example` в новый файл `.env` и замените заполнители на ваши фактические значения:

```
cp .env.example .env
# Затем отредактируйте .env с помощью вашего любимого текстового редактора
nano .env  # или vim, code, ...
```
Содержимое файла `.env` должно быть примерно таким:

```
DJANGO_SETTINGS_MODULE=drf_project.settings
DATABASE_URL=postgres://user:password@db:5432/db
CELERY_BROKER_URL=redis://redis:6379/0
CELERY_RESULT_BACKEND=redis://redis:6379/0
SECRET_KEY=your_secret_key_here
DEBUG=True
POSTGRES_USER=myuser
POSTGRES_PASSWORD=mypassword
POSTGRES_DB=mydatabase
```
2. Запустите проект с помощью Docker Compose:

```
docker-compose up --build
```

Эта команда соберет (если необходимо) и запустит все сервисы, определенные в файле `docker-compose.yaml`.  
Добавьте флаг `-d`, чтобы запустить контейнеры в фоновом режиме (`docker-compose up -d`).

3. (При первом запуске) Примените миграции и соберите статику:

```
docker-compose exec web python manage.py migrate
docker-compose exec web python manage.py collectstatic --noinput
```
Эти команды выполняются внутри контейнера `web` (Django).

4. Проверка работоспособности

* Web-сервис (Django):
    *   Откройте веб-браузер и перейдите по адресу `http://localhost:8000/`.
    *   Убедитесь, что вы видите страницу API.
    *   Проверьте, что вы можете выполнять основные операции (например, создавать, читать, обновлять, удалять данные).
    *   Проверьте эндпоинт `/admin/` для доступа к административной панели Django.

* База данных (PostgreSQL):
    *   Убедитесь, что Django может подключаться к базе данных и выполнять запросы. Если вы видите ошибки, связанные с базой данных, проверьте переменные окружения в файле `.env` (имя пользователя, пароль, имя базы данных, хост).
    *   (Опционально) Подключитесь к базе данных с помощью клиента PostgreSQL (например, `psql`) для прямой проверки.

* Redis:
    *   Если вы используете Celery, убедитесь, что Redis работает, проверив логи Celery worker и beat.
    *   (Опционально) Подключитесь к Redis с помощью клиента Redis (например, `redis-cli`) и выполните команду `PING`. Он должен вернуть `PONG`.

* Celery:
    *  Проверьте логи Celery, чтобы убедиться, что он успешно подключается к Redis и обрабатывает задачи.  Ищите сообщения "celery started" или "task received".
    *  Если задача, которую вы ждете не появляется - убедитесь, что redis запущен.

* Celery Beat:
   *   Проверьте логи Celery Beat, чтобы убедиться, что он успешно запускает запланированные задачи. Ищите сообщения "beat: Starting..." и "beat: Ticking..."

5. Остановка проекта


```
docker-compose down
```

### *Проект содержит:*

#### Приложение `materials` в которой реализованно следующее:

1. `migrations/`: миграции. 
2. `fixtures/`: фикстура для создания группы.
3. `__init__.py`: инициализация.
4. `admin.py`: файл для регистрации моделей в административной панели Django.
5. `views.py`: файл для создания контроллеров (представлений).
6. `apps.py`: файл с конфигурацией приложения. 
7. `models.py`: файл, содержащий определения моделей.
8. `tests.py`: файл для написания тестов.
9. `urls.py`: маршрутизация для проекта.
10. `paginators.py`: файл пагинации.
11. `permmissions.py`: файл прав доступа.
12. `serializers.py`: файл для сериализатора.
13. `services.py`: файл сервиса.
14. `tasks.py`: файл задач.
15. `validators.py`: файл валидации.

#### Приложение `users` в которой реализованно следующее:

1. `migrations/`: миграции. 
2. `fixtures/`: фикстура для создания оплаты.
3. `__init__.py`: инициализация.
4. `admin.py`: файл для регистрации моделей в административной панели Django.
5. `views.py`: файл для создания контроллеров (представлений).
6. `apps.py`: файл с конфигурацией приложения. 
7. `models.py`: файл, содержащий определения моделей.
8. `tests.py`: файл для написания тестов.
9. `urls.py`: маршрутизация для проекта.
10. `permmissions.py`: файл прав доступа.
11. `serializers.py`: файл для сериализатора.

#### Директорию `config` в которой реализованно следующее:

1. `__init__.py`: пакет.
2. `asgi.py`: содержит настройки для серверного интерфейса ASGI.
3. `settings.py`: содержит все основные настройки Django проекта.
4. `urls.py`: маршрутизация для проекта.
5. `wsgi.py`: настройки для серверного интерфейса WSGI.
6. `celery`: настройка celery для проекта.

#### В корне проекта:

1. `manage.py`: скрипт командной строки, созданный Django.
2. `env.example`: файл переменных окружения.
3. `docker-compose.yml`: файл для работы docker-compose.
4. `Dockerfile`: файл с инструкциями для автоматического создания Docker-образов.
