## **Установка:**

Версия python для данного проекта `^3.13`
Версия Django для данного проекта `^5.2`
Установленный Docker и Docker Compose (версия 3.9 или выше)

1. Установите Poetry:
```
https://install.python-poetry.org | python -
```
2. Клонируйте репозиторий:
```
git clone https://github.com/KolDaria/drf_project
```
3. Установите зависимости:
```

```

## **Настройка и Деплой**

Этот раздел содержит подробные инструкции по настройке удаленного сервера и деплою вашего приложения. 
Следуйте этим шагам, чтобы успешно развернуть проект.

### **1. Подготовка Удаленного Сервера**

Перед деплоем убедитесь, что ваш удаленный сервер готов к работе.

#### **1.1. Требования к Серверу:**

Операционная система: Ubuntu 20.04 LTS (или совместимая)

SSH доступ: Доступ по SSH с правами пользователя sudo.

Git: Установленный Git (sudo apt update && sudo apt install git -y).

Python: Рекомендуемая версия Python (3.12).

Установка Python (пример для Ubuntu):
```bash

sudo apt update
sudo apt install python3 python3-pip python3-venv -y
```

Poetry: Установленный Poetry для управления зависимостями.

Установка Poetry:
```bash

curl -sSL https://install.python-poetry.org | python3 -
```

Добавление Poetry в PATH (если необходимо, обычно происходит автоматически):
```bash

# Добавьте это в ваш ~/.bashrc или ~/.zshrc
export PATH="$HOME/.local/bin:$PATH"
source ~/.bashrc # или source ~/.zshrc
```
Проверка установки:
```bash

poetry --version
```

Docker: Приложение использует Docker и Docker Compose.

Установка Docker: Следуйте официальным инструкциям для вашей ОС: https://docs.docker.com/engine/install/ubuntu/

Установка Docker Compose: Следуйте официальным инструкциям: https://docs.docker.com/compose/install/

#### **1.2. Настройка SSH Ключей:**

Для безопасного доступа к серверу рекомендуется использовать SSH ключи.

Сгенерируйте SSH ключ на вашем локальном компьютере (если еще не сделано):
```bash

ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
При запросе пути сохранения нажмите Enter (для стандартного расположения ~/.ssh/id_rsa).
```

Скопируйте публичный ключ на удаленный сервер:
```bash

ssh-copy-id user@your_server_ip
```
Где user - имя пользователя на сервере, а your_server_ip - IP-адрес вашего сервера.

### **2. Процесс Деплоя**

Деплой приложения автоматизирован с помощью workflow, который запускается при определенных действиях.

#### **2.1. Запуск Workflow Деплоя:**

Workflow для деплоя обычно запускается при:

Пуш в определенную ветку (например, main или develop): При каждом пуше в эту ветку будет инициирован процесс сборки и деплоя.
Ручной запуск: Вы можете вручную запустить workflow через интерфейс CI/CD платформы (например, GitHub Actions, GitLab CI).
Чтобы запустить workflow вручную (пример для GitHub Actions):

Перейдите в раздел “Actions” вашего репозитория.
Найдите workflow, отвечающий за деплой.
Нажмите кнопку “Run workflow” и выберите ветку, из которой будет производиться деплой.

#### **2.2. Шаги Workflow:**

Workflow деплоя состоит из следующих ключевых этапов:

Checkout Code: Клонирование последней версии кода из репозитория.
Setup Environment: Настройка необходимой среды.
Активация виртуального окружения:
```bash

python3 -m venv .venv
source .venv/bin/activate
```

Установка зависимостей с помощью Poetry:
```bash

poetry install --no-dev --no-root
--no-dev: Игнорирует зависимости для разработки.
--no-root: Не устанавливает само приложение как пакет, только его зависимости.
```

Run Tests: Выполнение автоматических тестов с помощью Poetry:
```bash

poetry run pytest 
```
Build Application: Приложение требует сборки выполните соответствующие команды.
Deploy to Server:
SSH Connection: Установление SSH-соединения с удаленным сервером.
File Transfer: Копирование собранных файлов приложения и pyproject.toml на сервер (например, с помощью rsync или scp).
Install Dependencies on Server: На удаленном сервере, после копирования кода:
```bash

# Перейдите в директорию проекта на сервере
cd /path/to/your/app

# Активируйте виртуальное окружение (если используется)
source .venv/bin/activate

# Установите зависимости
poetry install --no-dev
```

## **Использование:**

1. Создайте файл `.env`:
Скопируйте содержимое файла `.env.example` в новый файл `.env` и замените заполнители на ваши фактические значения:

```
cp .env.example .env
# Затем отредактируйте .env с помощью вашего любимого текстового редактора
nano .env  # или vim, code, ...
```
Содержимое файла `.env` должно быть примерно таким:

```
DJANGO_SETTINGS_MODULE=drf_project.settings
DATABASE_URL=postgres://user:password@db:5432/db
CELERY_BROKER_URL=redis://redis:6379/0
CELERY_RESULT_BACKEND=redis://redis:6379/0
SECRET_KEY=your_secret_key_here
DEBUG=True
POSTGRES_USER=myuser
POSTGRES_PASSWORD=mypassword
POSTGRES_DB=mydatabase
```
2. Запустите проект с помощью Docker Compose:

```
docker-compose up --build
```

Эта команда соберет (если необходимо) и запустит все сервисы, определенные в файле `docker-compose.yaml`.  
Добавьте флаг `-d`, чтобы запустить контейнеры в фоновом режиме (`docker-compose up -d`).

3. (При первом запуске) Примените миграции и соберите статику:

```
docker-compose exec web python manage.py migrate
docker-compose exec web python manage.py collectstatic --noinput
```
Эти команды выполняются внутри контейнера `web` (Django).

4. Проверка работоспособности

* Web-сервис (Django):
    *   Откройте веб-браузер и перейдите по адресу `http://localhost:8000/`.
    *   Убедитесь, что вы видите страницу API.
    *   Проверьте, что вы можете выполнять основные операции (например, создавать, читать, обновлять, удалять данные).
    *   Проверьте эндпоинт `/admin/` для доступа к административной панели Django.

* База данных (PostgreSQL):
    *   Убедитесь, что Django может подключаться к базе данных и выполнять запросы. Если вы видите ошибки, связанные с базой данных, проверьте переменные окружения в файле `.env` (имя пользователя, пароль, имя базы данных, хост).
    *   (Опционально) Подключитесь к базе данных с помощью клиента PostgreSQL (например, `psql`) для прямой проверки.

* Redis:
    *   Если вы используете Celery, убедитесь, что Redis работает, проверив логи Celery worker и beat.
    *   (Опционально) Подключитесь к Redis с помощью клиента Redis (например, `redis-cli`) и выполните команду `PING`. Он должен вернуть `PONG`.

* Celery:
    *  Проверьте логи Celery, чтобы убедиться, что он успешно подключается к Redis и обрабатывает задачи.  Ищите сообщения "celery started" или "task received".
    *  Если задача, которую вы ждете не появляется - убедитесь, что redis запущен.

* Celery Beat:
   *   Проверьте логи Celery Beat, чтобы убедиться, что он успешно запускает запланированные задачи. Ищите сообщения "beat: Starting..." и "beat: Ticking..."

5. Остановка проекта


```
docker-compose down
```

### *Проект содержит:*

4. `admin.py`: файл для регистрации моделей в административной панели Django.

6. `apps.py`: файл с конфигурацией приложения. 
7. `models.py`: файл, содержащий определения моделей.
8. `tests.py`: файл для написания тестов.
9. `urls.py`: маршрутизация для проекта.
10. `paginators.py`: файл пагинации.
11. `permmissions.py`: файл прав доступа.
12. `serializers.py`: файл для сериализатора.
13. `services.py`: файл сервиса.
14. `tasks.py`: файл задач.
15. `validators.py`: файл валидации.

#### Приложение `users` в которой реализованно следующее:

1. `migrations/`: миграции. 
2. `fixtures/`: фикстура для создания оплаты.
3. `__init__.py`: инициализация.
4. `admin.py`: файл для регистрации моделей в административной панели Django.
5. `views.py`: файл для создания контроллеров (представлений).

9. `urls.py`: маршрутизация для проекта.
10. `permmissions.py`: файл прав доступа.
